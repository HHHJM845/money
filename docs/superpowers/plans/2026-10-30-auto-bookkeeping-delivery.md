# 自动收支记账分阶段交付计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans 执行单个阶段；主代理负责接口收口、集成和验收。分阶段不代表删减已确认的首版范围。

**Goal:** 将现有个人网页账本与 Android 试验工程改造成手机自动采集、双端纠错和联网同步的完整收支账本。

**Architecture:** 原生 Android 通过 Room 保存账本和持久操作队列；Web/Android 使用同一套业务契约，通过 Vercel Functions 与 Supabase PostgreSQL 同步。采集和 AI/OCR 只负责生成结构化输入，统一账务规则负责入账。

**Tech Stack:** Kotlin、Compose Material 3、Room、Android 系统采集服务；React 19/Vite/TypeScript；Node 22、pg、PostgreSQL。WorkManager 和 OCR 等依赖在所属阶段核实后引入，不进行无关升级。

## Global Constraints

- 设计基线：`docs/superpowers/specs/2026-10-30-auto-bookkeeping-design.md`；决策表含 84 个编号，所有首版决策均需映射到本计划。
- 单人、一个日常账本、人民币；账单/统计/我的三导航，无股票或投资看板。
- 现有生产数据保留，代码与 SQL 在隔离数据中验证后再部署；本计划不执行云端 SQL，不修改域名、秘密或连接配置。
- 数据库结构改动同步维护 `doc/sql/init.sql`、按顺序追加 `doc/sql/increment.sql`；Android SQLite 使用 `doc/sql/android/` 对应文件。中文字段/表注释，不创建外键，不创建框架迁移文件。
- 采用本地事务及服务端事务各自原子，网络重试幂等；不得将两者描述为跨网络同一事务。
- 金额是整数分，超精度/超范围有明确错误；所有客户端和服务端共用限制和合成样例。
- 不提交密钥、本机路径、`.local/`、测试凭据或数据库。文档不自动提交推送。
- AI01 服务商和 AI02 费用额度仍待指定，不能虚构默认服务或发起付费调用；可完成其接口和未配置状态。
- 保留已批准的隐私范围，不能为了方便识别或测试扩大读取/上传范围。
